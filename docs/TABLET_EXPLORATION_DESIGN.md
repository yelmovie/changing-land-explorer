# 움직이는 지오밸리 태블릿 탐구 경험 설계

작성일: 2026-10-16  
상태: 사용자 검토 의견을 반영한 후속 구현 설계. 이 문서의 신규 기능은 아직 구현되지 않았다.  
대상: 초등 4학년, 태블릿 가로 화면과 전자칠판.

## 1. 목표와 적용 범위

학생이 직접 만든 예상, 실험 조건, 관찰 증거와 경로가 화면의 변화와 다음 활동에 영향을 주게 한다. 각 미션에 종이의 정지 그림으로 전달하기 어려운 대표 경험을 하나씩 둔다. 목표 경험은 “내가 바꾸니 달라졌고, 다시 살펴보니 이유를 알겠다”이다.

기존의 5개 미션 × A/B 활동 2장, 총 10개 활동 구조를 유지한다. 선택 맵만 2.5D 픽셀아트 RPG이며 활동·엔딩은 2D다. 지오밸리에서 복구하는 것은 관측 기록과 안내 시스템이다. 학생의 정답이 자연현상을 멈추거나 재해를 없애지는 않는다.

현재 앱에는 5개 미션마다 4개 내부 단계가 있다. 화면 수를 20개로 늘리지 않고, 내부 단계 0·1을 A 활동, 2·3을 B 활동 안의 작업 상태로 통합한다. 활동 안에서 장면을 유지하며 도구와 목표만 바꾸고, 앞서 모은 증거는 계속 보인다.

### 현재 구현에서 바꿀 부분

| 현재 상태 | 설계 변경 |
|---|---|
| 물 양별 정해진 연출과 결과 문장 | 동일한 초기 지형·동일 시간의 두 실험, 재현 가능한 변화 데이터와 동시 되감기 |
| 예상핀 위치가 결과 설명에 반영되지 않음 | 최초 예상과 실제 변화 위치를 겹쳐 보고 예상 수정 이유 남기기 |
| 관찰 지점 방문 수와 문장 분류 중심 | 학생이 채집한 사진 범위·위치·시점이 붙은 증거로 설명하기 |
| 대피 정답 통로 한 경로, 출발 전 일괄 오류 | 여러 안전 경로 허용, 유효한 구간 재생, 위험 직전 정지, 해당 구간 수정 |
| 오른쪽 설명과 하단 캐릭터가 조작 공간을 차지함 | 큰 실험 무대, 접히는 수첩, 고정 도구줄, 캐릭터 전용 피드백 공간 |
| 공통 완료 문장 중심의 엔딩 | 내 실험 비교·관찰 표시·도시 안내판·경로 재생을 묶은 탐험 기록 |

코드 적용 대상은 기존 Vanilla JavaScript + Canvas + DOM 구조다. 프레임워크 교체, 서버, 로그인, 카메라·마이크·기기 기울기 권한, 전체 3D 전환은 이번 설계에 포함하지 않는다. 한 손가락으로 모든 필수 활동을 끝낼 수 있고 마우스·키보드·전자칠판에서도 같은 학습 결과를 만들 수 있다.

## 2. 공통 학습 흐름과 완료 원칙

**예상하기 → 조작하기 → 변화 살피기 → 비교하고 고치기 → 증거 남기기 → 새 상황에 사용하기**

- 예상은 맞고 틀림으로 점수를 주지 않는다. 관찰 후 예상과 결과를 연결해 설명하는 행동을 남긴다.
- 버튼 클릭 횟수, 막대를 양 끝까지 움직인 횟수, 문지른 면적만으로 학습 완료를 판정하지 않는다.
- 탐구 도중에는 여러 답을 허용하고, 제출 시 증거의 대상·시점·특징과 설명의 연결을 확인한다.
- 필요한 증거 수는 하한이다. 같은 사진을 중복 저장하거나 같은 특징을 두 번 선택해도 서로 다른 근거로 세지 않는다.
- 모든 오답은 대상 주변의 표시와 짧은 이유로 안내한다. 속도 경쟁·목숨·감점·강제 반복 문지르기를 두지 않는다.
- 드래그가 어려운 학생에게 선택 후 위치 누르기, 확대 버튼, 방향 버튼을 제공한다. 대체 조작도 자유로운 선택과 동일한 판정을 보장한다.
- 수첩을 닫거나 장면을 나가도 예상·진행 중 조건·증거가 유지된다. 실행 중 실험은 일시정지 상태로 복구한다.

## 3. 화면과 터치 디자인

### 3.1 기본 화면 배치

1280×720 CSS px 기준으로 세로 공간을 다음처럼 나눈다. 실제 앱은 visualViewport와 안전 여백을 기준으로 재계산한다. 전체 화면을 축소해서 글자를 작게 만드는 방식은 쓰지 않는다.

| 영역 | 기준 높이 | 내용 |
|---|---:|---|
| 공통 상단 | 64px | 좌측 홈·이전, 중앙 장소, 우측 가방·소리·설정 |
| 현재 목표 | 56px | 짧은 행동 지시, A/B 진행, 필요한 증거 수 |
| 탐구 공간 | 448px | 실험 대상, 직접 조작 도구, 접힌 수첩 입구 |
| 도구줄 | 72px | 현재 작업에 필요한 도구 최대 3개와 주 행동 1개 |
| 피드백 | 56px | 전용 영역 안의 작은 캐릭터와 1~2줄 안내 |
| 영역 사이 간격 합계 | 24px | 겹침 방지용 여백 |

가로 24px 안전 여백을 기본으로 한다. 비교 화면은 무대를 좌우로 나눠 같은 배율의 대상을 보여준다. 수첩은 기본적으로 접혀 있고, 열면 무대 일부를 가리는 별도 패널로 표시하며 실험을 일시정지한다. 작은 화면에서는 수첩을 전체 패널로 열고 닫으면 이전 관찰 위치로 돌아온다.

- 1280×800: 남는 80px은 탐구 공간에 추가한다.
- 1024×600: 상단 56, 목표 48, 무대 360, 도구 64, 피드백 48, 간격 24px로 배치한다. 공통 버튼은 48px, 수첩은 전체 패널을 쓴다.
- 그보다 낮은 화면: 부가 설명을 도움말로 이동하고 조작 영역은 유지한다. 세로 모드는 순차 카드 배치와 가로 전환 안내를 제공하며 사용을 차단하지 않는다.
- 창 높이·주소창·회전이 바뀌면 캔버스의 화면 좌표와 입력 좌표를 함께 갱신한다. 여백을 포함한 잘못된 좌표 환산을 금지한다.

### 3.2 도구와 시각 언어

- 핵심 조작 손잡이 56×56px, 기타 버튼 최소 48×48px. 핀과 선의 실제 터치 판정 영역은 보이는 표시보다 넓게 확보한다.
- 본문·버튼 18~20px, 제목 26~32px, 보조 안내 14~16px. 중요한 학습 지시를 보조 크기로 내리지 않는다.
- 예상은 황금색 점선, 실제 관찰은 청록 실선, 수정 필요 구간은 주황색 사선과 아이콘, 완료는 초록 체크로 표시한다. 색만으로 의미를 구별하지 않는다.
- 기본 색상은 종이색 #FFFAF0, 짙은 녹색 #246B58, 글자 #243E36을 계승한다. 흙·물·암석은 관찰 가능한 자연색을 유지한다.
- 실험 무대 뒤 배경은 대비와 채도를 낮추고, 조작 대상의 외곽·음영·재질 표현을 먼저 강화한다. 화산과 강을 단순한 평면 삼각형·굵은 선만으로 표현하지 않는다.
- 이동식 돋보기는 손가락 위쪽에 관찰 창이 나타나게 한다. 실제 채집 좌표는 손가락 아래 표적과 선으로 연결해 모호하지 않게 한다.
- 시간 막대와 비교 경계는 대상 바로 아래·경계 위에 둔다. 별도의 작은 슬라이더를 찾아야만 조작할 수 있는 배치를 없앤다.
- 캐릭터는 피드백 영역을 벗어나지 않는다. 설명이 길면 ‘더 보기’를 열며 버튼과 무대를 덮지 않는다.
- 장면 안의 UI는 DOM/CSS/SVG, 자연물은 별도 이미지·Canvas 레이어로 구성한다. 장식 이미지에 버튼 글자를 넣지 않는다.

### 3.3 감각 피드백

도구를 잡으면 손잡이와 선택 대상이 강조된다. 물을 흘릴 때는 흐름과 흙 이동이 함께 나타나고, 기록은 수첩으로 짧게 이동한다. 소리는 조작·기록·완료를 구별하는 보조 수단이며 음소거에서도 같은 정보를 보여준다. 감소된 모션 설정에서는 흔들림·이동 장식을 줄이고 변화 상태와 경로 결과는 유지한다.

첨부한 [강 실험 비교 화면 와이어프레임](design/river-comparison-wireframe.svg)은 이 배치의 개념도다. 버튼과 자연물의 최종 아트가 아닌 정보 구조와 공간 비율을 검토하기 위한 그림이다.

## 4. 활동 01과 02 강의 비밀

### 01 흐르는 물 실험실

**대표 순간:** 같은 시각의 두 실험을 손가락 하나로 되돌리면 깎인 언덕과 쌓인 흙이 서로 다르게 복원된다. 최초 예상핀도 남아 있어 무엇이 예상과 달랐는지 볼 수 있다.

1. 마른 흙 언덕을 먼저 보여준다. 학생은 쌓일 것으로 예상하는 위치를 자유롭게 누른다. ‘낮은 곳에 놓기’ 같은 정답 방향 버튼은 제거한다.
2. 적은 물과 많은 물 중 첫 조건을 선택한다. 실험 동안 지형·흙 재료·관찰 시간은 동일하게 유지한다. 첫 버전에서는 물의 양만 바꾼다.
3. 물뿌리개를 표시된 시작점으로 옮겨 기울인다. 기울이는 동작은 실험 시작 조작이며, 선택한 양 이외의 숨은 조건을 바꾸지 않는다. 실행 버튼도 같은 실험을 시작한다.
4. 물길이 생기고 흙 알갱이가 깎인 곳에서 이동해 쌓인다. 입자, 지형 윤곽, 퇴적층은 같은 시점 데이터를 따른다.
5. 첫 결과를 보관하고 동일 초기 지형으로 되돌려 두 번째 조건을 실험한다. 이전 지형에 물을 더 붓는 누적 실험과 혼동하지 않게 ‘새 흙 언덕에서 비교’라고 표시한다.
6. 두 결과를 같은 배율로 나란히 놓는다. 공통 시간 손잡이로 두 실험의 동일 시점을 비교한다. 실험 시간은 관찰용 모형 시간이며 실제 지형 변화 속도를 뜻하지 않는다.
7. 깎인 곳·이동한 흔적·쌓인 곳에 증거핀을 붙인다. 예상핀과 최종 퇴적 범위를 겹쳐 보고 ‘예상과 같았어 / 달랐어’와 해당 장면을 연결한다. 다르다는 선택 자체는 오답이 아니다.

**완료:** 서로 다른 물 양의 완료된 실험 2개, 비교 장면 1쌍, 세 작용의 유효한 증거, 예상과 결과에 대한 회고 1개. 두 번 재생하거나 시간 막대 끝을 왕복하는 것만으로 완료하지 않는다.

**피드백:** 핀이 엉뚱한 곳이면 정답 위치를 즉시 찍어 주지 않고 선택 위치의 전후 윤곽을 겹쳐 보여준다. 학생이 다시 위치를 고르거나 도우미를 요청할 수 있다. 비교 사진의 시간·조건이 다르면 같은 조건으로 맞추는 버튼을 제공한다.

**저장:** 최초 예상핀, 수정핀, 두 실험의 조건과 재생 버전, 선택 시점, 증거 위치, 회고. 물의 양을 바꾸기만 해서는 저장된 과거 실험의 결과가 변하지 않는다.

### 02 강의 흔적 판독실

긴 강 풍경을 한 손가락으로 이동하며 조사한다. ‘관찰’과 ‘이동’ 모드를 명확히 구분하고, 관찰 모드에서 확대창을 옮겨 바위·모래·물길 폭·경사 자료를 채집한다. 범례와 방향을 항상 보여준다.

학생은 상류와 하류에서 각각 서로 다른 특징 2개를 채집한다. 각 사진에는 원래 강에서의 위치가 작은 지도로 붙는다. 채집 사진을 강 지도에 연결하고 01의 깎임·이동·쌓임 증거 중 관련 자료를 꺼내 설명한다. 사진과 실제 지점이 강조되며 대응 관계가 보인다.

**완료:** 상류·하류 각각 특징 2종의 증거와 해당 위치, 관찰 특징에 맞는 설명 연결. 미리 인쇄된 문장만 분류하는 활동은 짧은 정리 보조로 축소한다. 모든 강이 이 그림과 똑같다는 설명은 쓰지 않는다.

**보상:** 물길 렌즈와 내 강 변화 기록. 지도 관측소에는 학생이 고른 비교 사진을 볼 수 있는 기록 표지가 생긴다.

## 5. 활동 03과 04 깨어나는 화산

### 03 화산 모형 구성실

문장 대신 쟁반·산 모형·붉은 물통을 작업대에 배치한다. 올바르게 조립한 물체가 실제 모형의 일부로 남는다. ‘안쪽 보기’로 붉은 물의 위치를 확인하고 화면 속 손잡이를 직접 민다.

손잡이를 밀 때 모형 내부의 물과 바깥 경사면의 흐름이 연결돼 보인다. 손을 떼면 추가 주입은 멈추되 이미 나온 물은 정해진 모형 규칙에 따라 계속 흐른다. ‘관찰 멈춤’은 별도 기능으로 두어 손잡이 정지와 시간 정지를 혼동하지 않게 한다. 다시 시작해도 원래 실험 조건은 유지한다.

학생이 멈춘 장면에서 입구와 흐른 경로에 표시하고 비교용 사진 2장을 남긴다. 내부 보기에도 ‘가상 모형의 내부’라고 표시한다. 손잡이를 실제 화산의 발생 원인으로 설명하지 않는다.

**완료:** 모형 배치, 직접 실행, 입구와 경사면 흐름에 대한 서로 다른 증거 2개. 정밀한 조립 퍼즐이나 드래그 속도를 평가하지 않는다.

### 04 모형과 실제 화산 비교실

왼쪽에는 내가 만든 모형의 기록, 오른쪽에는 검수된 실제 화산 관찰 자료를 놓는다. 관찰 그림을 쓰는 경우 실제 촬영 영상처럼 표시하지 않는다. 학생이 두 자료의 대응 위치를 선으로 연결하고 ‘닮은 모습’ 또는 ‘다른 점’을 지정한다.

공통점은 나오는 입구와 경사면의 흐름으로, 차이는 재료·온도 또는 모형에 표현되지 않은 분출물로 찾는다. 용암·화산재·암석 조각·기체는 자료 속 대상과 설명을 연결한다. 관찰 그림의 기체 표현은 보조 표시임을 명시한다. 두 자료의 재생 시간을 맞춰 실제 현상이 같은 속도로 일어나는 것처럼 보여주지 않는다.

**완료:** 모형과 관찰 자료의 공통점 2개·차이점 2개, 분출물 4종과 근거 자료 연결. 이미 본 설명을 순서대로 누르는 것만으로 완료하지 않는다.

**보상:** 비교 카메라와 내가 연결한 비교판. 암석 활동에서 같은 배율의 두 관찰 기록을 나란히 놓는 데 사용한다. 관리자 직접 진입에서는 체험 도구를 제공하며 학생 획득 기록을 만들지 않는다.

## 6. 활동 05와 06 돌 속의 단서

### 05 암석 관찰실

**대표 순간:** 표본의 일부를 확대해 알갱이를 직접 표시하고, 같은 배율의 다른 표본과 나란히 놓아 차이를 발견한다.

이름을 숨긴 두 표본을 제공한다. 먼지 털기는 짧은 도입으로 두고 ‘관찰 준비 완료’ 버튼으로 건너뛸 수 있게 한다. 쓸어낸 양은 학습 완료 조건에서 제외한다.

표본을 선택한 뒤 돋보기를 움직이고 +/− 버튼 또는 지원 기기에서 두 손가락으로 확대한다. 확대 중심이 튀지 않으며 한 손가락으로 전 기능을 사용할 수 있다. 사진의 실제 해상도보다 확대해 새로운 무늬가 생기는 것처럼 보이지 않게 상한을 둔다.

색 증거는 표본 전체나 넓은 영역에서, 알갱이 증거는 확대 부분에서 채집한다. 학생이 알갱이를 표시할 수 있는 펜을 제공하되 선의 모양을 자동 정답 판정하지 않는다. ‘뚜렷하게 보이는 알갱이 / 잘 구별되지 않는 알갱이’와 검수된 영역 정보로 근거의 적합성을 확인한다.

비교 카메라는 단순히 기존 그림을 조금 크게 보여주는 기능이 아니라, 학생이 선택한 두 관찰 영역을 동기화된 배율로 비교하는 도구로 만든다. 앞·옆 사진은 같은 표본의 검수된 자료가 확보된 경우에만 추가한다.

**완료:** 두 표본 각각 색과 알갱이 증거 1개씩, 총 4개. 확대창을 움직인 거리나 펜으로 선을 그린 양은 평가하지 않는다.

### 06 암석 감정 증거판

표본에 이름표를 놓고, 05에서 만든 자기 사진 2종을 근거 칸에 연결한다. 제출 시 표본에서 채집 영역을 다시 강조한다. 근거가 부족하면 해당 위치의 관찰창으로 바로 돌아가며 기존 분류는 유지한다.

새 표본 C·D를 같은 도구로 관찰한 뒤 이름과 이유를 연결한다. 구멍 없는 표본이나 색감이 다른 표본을 포함하되 자료의 과학적 적합성을 먼저 확인한다. 새 표본에 기존 사진을 붙이는 경우 ‘비교 자료’로 표시하고, 새 표본 자체의 관찰 증거도 요구한다.

**완료:** 기본 표본 2개와 새 표본 2개에 대해 색·알갱이를 함께 사용한 분류. 구멍 유무만으로 통과시키지 않는다.

**보상:** 표본 상자. 학생이 채집한 확대 사진과 표시를 이름표와 함께 저장한다. 최종 문제에서 이 상자를 실제로 다시 열어 비교한다.

## 7. 활동 07과 08 도시의 시간여행

### 07 시간이 흐르는 화산도시

**대표 순간:** 같은 농장을 화면에 고정한 채 경계 손잡이를 움직이면 두 시기의 모습이 정확히 겹쳐 비교된다. 학생이 표시한 변화가 장소·시기와 함께 기록된다.

시간은 ‘분출 당시 / 안전 확인과 복구 이후 / 오랜 시간이 지난 뒤’의 세 상태로 구분한다. 임의의 연도나 하루 단위 카운터는 넣지 않는다. 중간 상태 그림을 확보하기 전까지는 기존 두 상태로 제공하고, 존재하지 않는 중간 장면을 보간해 사실처럼 보여주지 않는다.

공항·농장·온천을 조사한다. 장소를 선택하면 동일 좌표·배율로 고정되고, 비교 경계 위의 큰 손잡이를 직접 움직인다. 학생이 바뀐 부분을 누르면 두 시기의 대응 영역이 함께 강조된다. 시간 확인과 장소 선택만으로 기록되지 않고, 변화 설명을 하나 연결해야 증거가 만들어진다.

**완료:** 세 장소의 전후 증거쌍과 변화 설명. 위험·피해 근거와 안전 확인 후 이용·장기 변화 근거를 각각 포함한다. 시간 막대 왕복을 통과 조건으로 쓰지 않는다.

**자료 제작:** 하나의 도시 원도를 바탕으로 상태별 레이어를 바꾼다. 카메라·건물·도로가 다른 별개 그림을 전후 사진처럼 겹치지 않는다. 토양 변화와 시설 복구가 모두 똑같은 시간이 걸린다는 표현을 피한다.

### 08 주민 안내판 제작실

07에서 만든 사진을 주민의 질문에 연결한다. 공항 이용자·농장 주민·온천 방문자의 질문 중 하나를 먼저 고르고, 모든 질문을 순서대로 해결한다. 각 안내는 ‘장소·시기·관찰한 변화·전할 내용’으로 구성한다.

학생은 자기 사진과 검수된 안내 문구를 선택·연결하고 필요하면 짧은 메모를 추가한다. 자유 문장 의미 분석이나 AI 자동 채점은 도입하지 않는다. 규칙 기반 판정은 근거·시기·문구 연결에만 적용하며 메모는 별도로 보존한다.

안내가 완성되면 도시 게시판에 실제 학생 결과물이 나타나고 주민이 안내를 읽거나 대체 일정을 확인하는 짧은 반응을 보인다. 잘못된 안내에는 근거 사진의 시점이 강조되고 수정할 칸으로 돌아온다.

**완료:** 세 장소 안내, 각 안내에 해당 장소의 증거쌍 연결, 현재 위험과 이후 이용의 구별. “분출 직후 곧바로 농사가 잘된다”처럼 시점을 혼동한 연결은 수정하도록 한다.

**보상:** 안전 나침반과 내 안내판. 도시 정보망이 복구되지만 학생 안내로 분출 자체가 멈추지는 않는다.

## 8. 활동 09와 10 우리의 안전길

### 09 흔들리는 중 몸 보호하기

주변을 조사해 위험한 물체와 몸을 보호할 장소에 표시한다. 학생은 리버를 튼튼한 책상 아래로 이동시키고 몸 보호·책상 다리 잡기를 장면 속 조작점으로 수행한다. 길게 누르기나 여러 손가락 동시 입력은 필수가 아니다.

상태는 ‘주변 조사 → 흔들리는 중 → 멈춤 확인 → 안내에 따라 이동 준비’로 분리한다. 보호 동작을 완료했다고 지진이 멈추는 인과관계로 보이지 않게 한다. 교육용 흔들림 타임라인은 보호 동작과 독립적으로 진행하고, 흔들림 종료와 보호 수행 기록을 각각 확인한다. 놓친 동작은 짧은 연습 재생에서 수행할 수 있다.

**완료:** 주변 위험·보호 위치 기록, 보호 행동 수행, 멈춘 뒤 이동 상태 구별. 캐릭터 부상·실패 점수·카운트다운은 없다.

### 10 안전한 길을 시험하고 고치기

**대표 순간:** 내가 그린 길을 따라 리버가 이동하다 위험 구간 바로 앞에서 멈춘다. 표시된 구간만 고치면 앞서 만든 경로를 유지한 채 다시 확인할 수 있다.

1. 교사가 안내한 목적지가 표시된 학교 평면도에서 길을 그린다. 출발점은 이전 활동의 위치와 연결하고, 층 이동은 계단 연결 표시로 명확하게 표현한다.
2. 통행 가능한 공간을 면 영역으로 정의하고, 서로 다른 안전 경로가 최소 2개 존재하도록 배치한다. 정해진 꺾은선 주변만 정답으로 처리하지 않는다.
3. ‘이 길로 확인’을 누르면 전체 경로를 먼저 계산하되 학생에게는 유효한 구간의 이동을 보여준다. 처음 만나는 위험·벽·잘못된 연결 지점 직전에 멈춘다.
4. 위험 대상과 수정 구간, 이유를 한 화면에 표시한다. 건너뛸 수 없는 구간을 빨간 정답선으로 알려주는 대신 지형과 위험을 다시 살피게 한다.
5. 학생이 두 수정 손잡이 사이 구간만 다시 그린다. 앞뒤 경로는 보존하고 연결부까지 재검사한다. 이어서 확인 또는 처음부터 재생을 고를 수 있다.
6. 목적지에 도착하면 선택한 길과 피한 위험을 기록한다. 기본 과제 후 야외 상황은 같은 원리를 다른 배치에 적용하는 전이 과제로 제공한다.

**완료:** 적절한 이동 상태, 올바른 시작·목적지, 전체 경로의 통행 가능성과 위험 회피, 지정된 안전 연결 조건 충족, 도착 재생 완료. 처음부터 안전한 길을 그렸다면 일부러 실패하거나 수정할 필요가 없다. 최단거리·속도로 등급을 매기지 않는다.

**입력 보정:** 손가락 떨림은 통행 가능 영역 안에서만 완화한다. 벽·위험을 가로지르는 선을 자동으로 안전 경로로 바꾸지 않는다. 경로는 점 간 선분 전체와 캐릭터의 폭을 검사한다. 화면의 위험 표시와 판정 영역은 같은 좌표 데이터를 쓴다.

**안전 내용 기준:** 흔들리는 동안 책상 아래에서 몸을 보호하고 다리를 잡기, 멈춘 뒤 안내에 따라 질서 있게 이동하기, 계단 이용, 건물과 거리를 두고 넓은 장소로 이동한다는 기준은 [국민안전24 지진 행동요령](https://www.safekorea.go.kr/safekorea-kor/acts/nacts/action-guide.do?actsHeaderTitle=%EC%A7%80%EC%A7%84&category=earthQuake&menuSn=4)을 따른다. 게임 속 가상 지도는 실제 학교의 지정 대피 경로를 대체하지 않는다.

## 9. 탐험 수첩과 마지막 장면

수첩은 설명문 모음이 아니라 학생이 만든 증거의 보관함이다. 각 증거에는 작은 그림, 대상, 조건 또는 시기, 학생 표시, 설명이 함께 나타난다. 증거를 누르면 원래 관찰 위치·배율·시점으로 돌아간다.

| 기록 | 실제로 다시 보여줄 내용 | 다음 사용처 |
|---|---|---|
| 강 변화 | 예상핀과 두 실험의 비교 시점·작용 표시 | 강 풍경 해석, 새 모래 언덕 문제 |
| 화산 비교 | 내가 멈춘 모형 장면과 대응 연결 | 최종 비교 기록 |
| 암석 관찰 | 확대 영역·배율·알갱이 표시·이름 | 새 표본 감정, 최종 표본 문제 |
| 도시 변화 | 같은 장소의 전후 사진·시간·안내 | 주민 안내판, 최종 기록 |
| 안전길 | 보호 행동·완성 경로·수정 전후 구간 | 엔딩 재생, 다른 장소 적용 |

최종 기록탑에는 도구 이름끼리 맞추는 퍼즐 대신 각 미션의 대표 증거를 직접 꽂는다. 새 물길, 새 암석, 새 안전 상황의 3개 문제에서는 관련 수첩을 열어 근거를 사용한다. 해당 미션과 같은 조작을 축소 재사용하고 새로운 문장 분류 화면만 반복하지 않는다.

엔딩에는 학생이 선택한 대표 증거 5개를 보여준다. 강 비교는 되감기, 암석은 표시한 부분 확대, 도시는 안내판 펼치기, 안전길은 경로 재생으로 다시 볼 수 있다. 인증서의 출력 문구는 유지하되 옆에 실제 탐험 기록을 확인할 수 있게 한다. 별명은 출력 직전 임시 입력만 허용하며 저장하지 않는다.

## 10. 구현 구조와 기록 규칙

### 10.1 기존 코드 적용 위치

| 파일 | 변경 책임 |
|---|---|
| src/main.js | 활동 A/B 안의 상태 전환, 무대 중심 레이아웃 연결, 엄격한 완료 판정 호출 |
| src/nature.js | 동일 조건 실험과 재생, 예상 비교, 화산 조립·직접 조작 |
| src/observations.js | 증거 채집·동일 배율 비교, 도시 좌표 고정·안내판 구성 |
| src/safety.js | 안전 상태 전환, 여러 통행 영역, 위험 직전 정지·부분 경로 수정 |
| src/model.js | 검증 함수, 기록 참조와 저장 데이터 검증, 기존 기록 이관 |
| src/ui.js 및 src/style.css | 직접 조작 손잡이, 수첩 패널, 공통 도구줄, 터치 좌표와 반응형 |

필요할 때 evidence.js, replay.js, 학습 데이터 파일을 추가한다. 기존 이벤트·캔버스 정리 함수를 유지하며 한 미션씩 교체한다. 과학 자료·핫스폿·정답 근거·위험 영역을 데이터로 분리하고 화면 코드에 반복 작성하지 않는다.

### 10.2 증거 데이터

공통 증거에는 id, stageId, activityId, sourceAssetId, sourceVersion, sourceRegion, condition, time, annotations, claimId, revision을 둔다. 그림 범위와 핀 좌표는 0~1의 원본 좌표로 저장해 화면 회전에도 유지한다. 설명은 학생의 선택과 관찰 기록에서 만들며 제출하지 않은 관찰을 자동으로 작성하지 않는다.

화면 캡처 이미지를 매번 localStorage에 넣지 않는다. 원본 에셋 ID와 잘라낼 범위·시점·표시를 저장해 미리보기를 다시 그린다. 실험은 지형 ID, 조건, 고정 seed, 모형 버전으로 재생한다. 모형 버전이 달라지면 과거 기록을 새 규칙으로 몰래 다시 계산하지 않고 기존 재생 규칙을 유지하거나 보존된 결과 요약을 표시한다.

권장 상한은 증거 60개, 강 실험 최근 6회와 대표 2회, 경로 원본별 단순화된 점 300개, 수정 이력 최근 5개다. 대표로 선택한 기록은 자동 삭제하지 않는다. 이 상한은 성능 목표이며 실제 저장량을 측정해 조정한다. 펜 기록은 선분 단순화, 입력 저장은 조작 종료 또는 제한된 주기로 수행한다.

### 10.3 완료 판정과 회귀 방지

도시 비교의 첫 진입에서 관찰 전 진행이 가능했던 문제를 우선 수정한다. 원인은 미설정 상태값을 포함한 조건식이 undefined를 반환하고, 공통 ready(value=true)가 이를 통과로 취급할 수 있는 구조다.

새 설계에서는 ready(value)의 기본값을 false로 하고 value === true인 경우에만 활성화한다. 완료 조건은 누락 필드를 false로 정규화하는 별도 검증 함수로 계산한다. 다음 버튼에서도 현재 증거 revision과 완료 조건을 재검증한다. 과거에 통과했더라도 근거를 수정·삭제했다면 현재 제출 상태는 다시 확인한다.

관리자 전체 해금은 화면 진입만 허용한다. 체험용 예시는 분리된 임시 상태와 ‘예시’ 표시를 사용하고 학생 완료 기록에 저장하지 않는다. 직접 진입한 B 활동은 필요한 도구와 예시 자료를 제공하되 관찰 완료 조건은 자동 통과시키지 않는다.

기존 v2 저장은 읽기만 하여 보존하고, 새 기록은 v3 키로 저장한다. 기존 획득 도구·완료·인증 이력은 유지한다. 좌표·시점이 없는 옛 기록에 새 증거를 임의 생성하지 않는다. ‘이전 탐험 기록’으로 보여주고 상세 기록이 필요한 새 과제에서는 추가 관찰로 이어 준다. 잘못된 데이터·저장 실패 시 앱은 계속 실행하며 저장 상태를 알린다.

## 11. 필요한 에셋과 실행 성능

### 에셋 제작 순서

1. 강: 초기 지형, 깎임 윤곽, 물길, 입자, 퇴적층을 분리한다. 두 조건의 비교 시점마다 지형과 입자가 일치하도록 작성·검수한다.
2. 안전: 복수의 안전 통로가 있는 하나의 학교 원도, 벽·계단 연결·위험·통행 가능 영역을 같은 좌표로 제작한다.
3. 암석: 실제 관찰 기준에 적합한 고해상도 표본과 확대 영역 정보를 확보한다. 기존 그림은 색·알갱이 판단이 가능한지 먼저 검수한다. 생성된 질감만으로 과학 판정 근거를 만들지 않는다.
4. 도시: 하나의 원도에 상태별 피해·복구·장기 이용 레이어를 제작한다. 같은 시설이 위치를 바꾸지 않게 한다.
5. 화산: 가상 모형의 내부·외부 레이어와 실제 관찰 자료를 별도로 준비한다. 출처·이용 권한·표현 한계를 자료 메타데이터로 남긴다.

강은 교육용 결정적 모형으로 구현한다. 두 조건에 맞는 검수된 변화 프레임과 동일한 시간 입력으로 재생하며, 실제 유체역학이나 모든 강의 변화를 예측하는 계산기로 표현하지 않는다. 물의 양 외 변수를 추가하는 것은 이 대표 경험을 검증한 이후의 확장이다.

### 로딩 예산과 성능 목표

새 초기 로딩 계획은 HTML, CSS, main/model/ui의 JS 3개, 한글·라틴 폰트 2개, 메인 지도·리버 이미지 2개로 총 9개 필수 요청이다. 첫 화면 전송량 1.5MiB 이하를 목표로 하며 현재 실측값은 아니다. 이를 위해 지도·활동·엔딩 모듈은 진입 시 불러오도록 정리한다. 실제 브라우저 요청 목록으로 숫자를 검증한다.

각 활동은 진입 시 필요한 자료만 불러오고 필수 전송량 2MiB 이하를 첫 목표로 잡는다. 큰 표본 원본과 추가 시간 상태는 해당 도구를 사용할 때 로드하고 실패 시 작은 자료와 재시도를 제공한다. 기존 빌드의 전체 파일 사전 캐시는 교실 동시 접속 비용을 측정한 뒤 초기 필수·활동별 캐시로 분리한다.

태블릿 조작 목표는 입력 후 시각 반응 100ms 이내, 재생 30fps 이상이다. 미달하면 입자·장식만 줄이고 지형·조건·판정은 유지한다. 수첩·설정이 열리거나 앱이 숨겨지면 실행을 멈춘다. 30대 동시 첫 진입과 실제 학교망 시험은 구현 후 별도 검증한다.

### 필수 수용 검사

- 강: 서로 다른 두 조건, 같은 초기 지형·시점, 양방향 되감기, 예상과 결과 표시가 일치한다. 조건 변경이 과거 결과를 덮어쓰지 않는다.
- 화산: 손잡이 입력과 관찰 시간 정지가 구분된다. 모형·실제 자료의 차이가 화면과 설명 모두에서 드러난다.
- 암석: 두 배율이 동기화되고 채집 범위·표시가 새로고침 뒤에도 유지된다. 동일 특징의 중복 증거로 완료되지 않는다.
- 도시: 첫 진입·다시 진입·관리자 진입 모두 관찰 없이 통과하지 않는다. 전후 같은 위치가 맞고 시점에 맞는 안내만 연결된다.
- 안전: 서로 다른 안전 경로가 통과한다. 벽·위험을 가로지르는 긴 선분은 실패한다. 실패 위치 직전 정지, 수정 구간 밖 보존, 재검사와 도착까지 확인한다.
- 입력: 손가락 떨림·화면 밖 드래그·pointercancel·두 번째 손가락·키보드 대체 조작에서 기록이나 상태가 깨지지 않는다.
- 화면: 1280×720, 1280×800, 1024×600, 세로 전환에서 주요 조작이 가려지지 않고 캐릭터와 버튼이 겹치지 않는다. QR 인앱 브라우저의 주소창 변화도 포함한다.
- 저장: 이전 v2, 새 v3, 누락된 필드, 저장 공간 부족, 관리자 예시를 각각 확인한다. 불완전 자료를 완료 증거로 취급하지 않는다.
- 엔딩: 저장된 학생 증거와 표시 내용이 일치하며 실제로 남기지 않은 관찰 문장이 추가되지 않는다.

교육 경험 확인은 교사 시연과 학생 사용 관찰로 진행한다. 학생이 ‘무엇을 바꿨는지, 무엇이 달라졌는지, 어떤 증거로 설명하는지’를 자기 결과물로 보여줄 수 있는지 확인한다. 화면을 모두 눌렀다는 사실만으로 설계가 성공했다고 판정하지 않는다.
