## 오프라인 재현

1. 새 컨텍스트에서 운영 첫 화면을 연다.
2. `navigator.serviceWorker.ready`와 controller 활성화를 확인한다.
3. 네트워크를 오프라인으로 바꾼다.
4. 새로고침한다.
5. 시작 버튼이 사라지고 ‘지오밸리로 가는 길을 준비하고 있어…’에서 멈춘다.

화면: `.work/audit-20261025/production-offline-first-reload.png`. 데이터: `audit-core.json`의 `offline`.

`scripts/build.mjs`의 precache에는 실제 초기 의존성 전체가 포함되어 있지 않다. HTML은 cache-first이며 즉시 갱신 절차도 충분하지 않다. 설치용 manifest 링크는 없다. PWA 설치 기능을 요청 없이 새로 추가하는 것은 필수 수정으로 제안하지 않는다. 첫 화면 복원과 실제 지원 범위 안내부터 보완해야 한다. 미방문 활동까지 끝내는 장기 오프라인 완주는 NOT TESTED다.

## 저장 충돌 재현

격리된 같은 origin의 두 창을 사용했다. B에 새 `river` 완료와 표식 기록을 저장한 다음, 이전 상태를 가진 A에서 소리 버튼만 눌렀다. B의 완료와 표식이 사라지고 경고도 없었다. 검사 결과 `newRecordPreserved=false`다.

`persistStudent()`는 기존 저장값 변경을 비교하지 않고 전체 스냅샷을 쓴다. 초기화 확인창이 열린 동안 다른 창이 갱신한 경우도 같은 보호가 필요하다. 원본 비교만으로 모든 경쟁 조건을 원자적으로 막았다고 주장하면 안 된다.

실제 사용자의 기록은 이 재현에 사용하지 않았다. 공용 기기·브라우저·주소별 저장이라는 안내는 현재 설정에 있다.
