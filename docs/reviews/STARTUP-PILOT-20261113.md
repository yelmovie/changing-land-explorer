# 움직이는 지오밸리 — 첫 화면과 엔진 진입 검증

2026-11-13 · 7번 · 로컬 수정 및 검증. 운영 주소는 https://geovalley.pages.dev/ 이며 배포하지 않았다.

첫 화면의 그림, 시작 버튼, 인트로 영상과 건너뛰기 동작을 유지했다. 타이틀을 지도 모듈에서 분리하고, 지도를 열거나 저장된 활동에 바로 진입할 때만 Phaser를 요청한다. 지도와 활동이 같은 엔진 요청을 공유한다. 지도에서 엔진을 못 받으면 기존 간단한 지도로 장소를 선택할 수 있고, ‘지도 다시 열기’로 움직이는 지도를 복구할 수 있다. 활동에서 엔진을 못 받으면 같은 활동을 다시 시도한다. 활동 코드 자체가 차단되면 ‘다시 열기’가 같은 위치를 기억한 채 문서를 새로 연다.

| 측정 구간 | 일반 로컬 전 → 후 | 10Mbps·40ms·CPU 4배 감속 전 → 후 |
|---|---:|---:|
| 첫 콘텐츠 표시 | 56 → 72ms | 540 → 600ms |
| 시작 버튼을 누를 수 있을 때까지 | 80 → 46ms | 2.48 → 1.05초 |
| 인트로 건너뛰기 → 지도 버튼 | 25 → 22ms | 69 → 493ms |
| 인트로 건너뛰기 → 움직이는 지도 완성 | 41 → 78ms | 1.16 → 3.67초 |
| 관측소 입장 → ‘물 주기’ 버튼 | 253 → 249ms | 4.74 → 4.52초 |

Chrome 1280×800, 같은 로컬 서버의 전후 빌드를 교대로 5회씩 측정한 중앙값. 매번 새 브라우저 컨텍스트, HTTP 캐시 및 서비스워커 차단, 이동 모션 줄이기 설정. 시작 버튼과 지도·활동 버튼은 클릭 위치가 실제로 열리는 시점 기준. 첫 화면 전에 받던 Phaser 전송량 약 1.20MB가 0이 됐으며, 지도 모듈도 시작 중에는 요청하지 않았다. 제한망에서는 엔진 다운로드가 지도 진입으로 이동해 움직이는 지도의 완성은 늦어졌다. 활동 구간은 지도가 열린 뒤 관측소 입장을 누르는 시점부터 별도로 쟀다. 학교 기기 또는 운영 서버 성능 수치는 아니다.

- 인트로를 끝까지 재생해도 지도에 연결됐다. 엔진 응답을 지연시키고 홈으로 돌아간 뒤 응답을 풀어도 홈에 지도가 나타나지 않았다.
- Phaser를 막은 채 인트로를 열고 건너뛴 뒤, 간단한 지도에서 물길 관측소로 들어갔다. 차단을 풀고 활동의 ‘다시 열기’를 눌러 ‘물 주기’를 실행했고, 첫 관찰 기록을 저장한 뒤 새로고침해도 남아 있는 것을 확인했다. 915×412 터치 화면에서는 ‘지도 다시 열기’로 움직이는 지도도 복구했다.
- 앱 진입 코드와 활동 모듈을 각각 차단해 ‘다시 열기’가 홈과 해당 활동을 복구하는지 확인했다.
- 서비스워커가 켜진 첫 화면에서도 엔진을 요청하거나 저장하지 않았다. 온라인으로 지도를 한 번 열어 저장한 다음 연결을 끊고 새로고침했을 때 활동이 열렸다. 이전 버전 캐시에 같은 버전의 엔진이 있으면 새 캐시로 이어받도록 했다.
