## 발견·수정한 진행 차단 문제

1. **제목:** 관찰 기록은 저장됐지만 완료 저장 전 종료되면 다음 발견이 영구 잠긴다.
2. **우선순위:** P1. 특정 중단 복구 상태에서 핵심 진행이 막힌다.
3. **화면:** 화산 연구소 활동 2/2의 분출물, 물길 관측소 활동 2/2의 상류·하류 관찰.
4. **재현:** `work.found`와 해당 실제 `evidence`가 모두 있으나 `chapter.tasks[phase].done`이 없는 저장 상태로 `setup()`을 실행한다. 숫자를 다시 누르거나 기존 확인 버튼을 실행한다.
5. **기대:** 이미 모은 실제 증거로 완료를 복구하거나 재확인 조작으로 진행할 수 있다.
6. **수정 전 실제:** 이미 `found`인 항목에서 먼저 반환해 완료 함수를 다시 호출하지 않는다. 3장면 모두 기록을 추가로 눌러도 `finishes=0`이었다. 학생은 모든 곳을 찾았는데 다음으로 갈 수 없다.
7. **근거:** 실제 활동 `setup()` + 기존 프로젝트 하네스. `record()`가 완료 저장 전에 개별 관찰을 저장하는 구조이며, 중간 저장을 복구 입력으로 재현했다. 물리 브라우저 종료 시점 자체를 강제로 맞춘 실험은 하지 않았다.
8. **관련 위치:** `src/adventure/volcano.js:169`의 `recorded/check/inspect`, `src/adventure/river.js:259`의 `recorded/check/observe`, `src/explore-ui.js:15`의 개별 기록 저장.
9. **적용:** 주 작업자가 실제 `kind/claim`이 맞는 증거와 `found`를 함께 검증한다. 최초 화면과 재클릭 때 완료를 재평가한다. 표시만 있고 증거가 없거나 잘못되었으면 재클릭으로 해당 증거를 다시 남긴다.
10. **위험·영향:** 화산 분출물과 강의 두 관찰 장면에 제한된다. `found` 개수만 믿고 완료시키지 않는다. 완료 장면 재관찰은 기록·완료를 다시 지급하지 않는다.
11. **검증:** `.work/final-audit/game/recover-probe.mjs` 3/3 통과. `scripts/autoplay.test.mjs`에 각 장면당 복구/유령 표시 거부·증거 회복/완료 중복 방지 3개씩 추가했다. 해당 시점 89개, 후속 통합 수정 후 최종 93개 통과했다.
12. **증거등급:** 확인됨(실제 함수 실행 하네스). 수정 후 브라우저 시각 점검은 통합 담당의 추가 결과와 함께 판단한다.

## 실제 드래그 끝점의 완료 정체 — 후속 수정

- **P1·화산 모형 활동 1/2의 주사기:** 통합 담당의 실제 완주에서, Phaser Scene에 드래그 임계값 8을 올바르게 적용하자 손잡이를 끝까지 이동해도 약 98%에 남아 다음 발견이 열리지 않았다. 이전에는 Game config에만 있던 임계값이 로컬 Phaser에서 무시돼 0으로 동작했다. 임계값 자체의 수정이 손떨림을 구별하면서 최초 이동 간격을 실제 드래그 입력에서 제외한 것이다.
- **기대:** 손잡이가 종단 근처에 도달하면 완료 위치에 붙고 흐름 관찰을 끝낼 수 있다. 물리적으로 100%인 단일 좌표를 정확히 맞출 필요가 없어야 한다.
- **적용:** 주 작업자가 `src/adventure/index.js`의 Scene에서 `scene.input.dragDistanceThreshold=8`을 명시하고, `src/adventure/volcano.js`의 `inject.push()`에서 95% 이상 입력을 1로 스냅했다. 아직 90%인 부분 이동은 원래대로 보존한다. 완료와 저장은 실제 흐름 업데이트가 끝날 때 이루어진다.
- **추가 검증:** `scripts/autoplay.test.mjs`의 `manual syringe endpoint...` 테스트에서 `onMove`와 `onDrop` 각각 90% 입력+6초는 미완료, 97% 입력+업데이트는 push/flow/modelTime=1·완료 1회, 완료 뒤 두 번 재입력·재생은 데이터/저장/기록/완료 중복 없음으로 확인했다. 전체 **93/93** 통과했다.
- **범위·한계:** 이 담당의 확인은 실제 입력 핸들러 실행 하네스다. 임계값 0과 브라우저 완료 정체의 최초 발견·수정 후 포인터 완주는 통합/디자인 담당의 실행 증거를 따른다. 점수나 장식 연출을 추가하지 않고 끝점 허용 범위만 고쳤다.
