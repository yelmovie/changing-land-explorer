## 적용한 기준과 기존 합의

- `iscream-settings`, `final-check`, `design`을 다시 읽고 적용했다. 하위 기준은 `learning-check`, `fun-check`, `tablet-check`, `media-check`, `classroom-ready`, `asset-audit`, `dokdo-design`이다. 같은 실행 결과를 각 영역에서 재사용했다.
- 사용자 전역 지침의 활동 UI, 기록·배포 검증, 기록 보관·시연 문서를 읽었다. 별도 등록된 `게임공통`이라는 SKILL.md는 찾지 못했다. 대신 열린 메모장의 「게임공통설계 프롬프트」와 프로젝트 `docs/UI_AND_ENGAGEMENT.md`를 대조했다.
- 프로젝트는 2026-10-12에 **단일 설정창, 전체 해금 스위치 하나, 시연 중 페이지별 진입 수단**을 합의했다. 따라서 접힘 카드가 없다는 사실이나 시연 바로가기 목록 자체를 결함으로 판정하지 않았다. 현재 공통 스킬의 기본 템플릿을 이유로 이 합의를 자동 변경하지 않는다.
- 배경 음악은 현재 사용하지 않는다. 없는 음악을 추가하거나 불필요한 음악 음량 UI를 새로 만드는 작업은 이번 필수 수정 범위가 아니다.
- 설정의 별도 교사용 해금 페이지는 없다. `설정 → 관리자 전체 해금 → 지도의 전체 화면`으로 들어간다. **해금 기능의 완전한 누락과, 발견하기 어렵거나 시연이 막히는 문제를 구분해야 한다.**

## 스테이지 매트릭스

O는 코드와 실행에서 확인한 구조, △는 해당 구성은 있으나 독립적인 게임성·재도전 동기 검증이 부족함을 뜻한다. 자동 검사에서 ‘조작 도움’이 유효한 대상을 대신 고르는 경우가 있어 독립적인 학습 성공으로 계산하지 않았다.

| 장소 | 판단·긴장 장치 | 게임 조작 | 즉시 보상 | 다시 할 이유 |
|---|---|---|---|---|
| 강 | O 예상과 실제, 물의 양만 바꿔 비교 | O 깃발·물 주기·시간 비교·흔적 연결 | O 물길 렌즈, 관찰 기록 | △ 다른 예상·조건을 비교할 수 있으나 완주 뒤 새 도전 예고는 약함 |
| 화산 | O 모형과 실제에서 같은 점/다른 점 찾기 | O 조립·밀기·분출물 관찰·흐른 길 추적 | O 비교 카메라 | △ 다른 관찰 가능, 새 재도전 목표는 불분명 |
| 암석 | O 이름보다 색·알갱이 근거가 먼저 | O 붓질·돋보기·두 근거·분류 | O 표본 상자 | △ 다른 방향/표본 적용은 있으나 무작위 조작 통과 여부 미검증 |
| 시간 관측소 | O 분출 직후와 안전 확인/오랜 시간 뒤 판단 | O 같은 장면 시간 손잡이·기록 연결·안내판 | O 안전 나침반 | △ 후반 안내판도 반복 조작 구조. 가장 약한 재플레이 후보로 후속 직접 검증 필요 |

학습 범위는 현무암·화강암 관찰, 화산 분출물과 모형의 한계, 피해와 이로움, 지진 대처에 연결된다. ‘분출 직후 바로 풍년’, ‘흔들리는 중 뛰어나가기’ 등을 정답으로 가르치는 분기는 확인하지 않았다. 일부러 모든 오답을 직접 밟은 전수 검사는 아니다. 성취기준 대조 출처: [경기도교육청 수업 설계 자료, PDF 85쪽](https://www.goe.go.kr/resource/old/BBSMSTR_000000030136/BBS_202411110127574203.pdf), [교육부 2022 개정 교육과정 고시](https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=141&boardSeq=93458&lev=0).

수정 순서는 **R1 저장 보호 → R2 교사용 시연 → R3/R6/R9 공통 UI → R4 오프라인 → R5/R7 설정·영상 → R8 연속 완주 → 출처 확인**을 권장한다. 위험은 저장 충돌 처리로 인한 저장 차단, 예시 기록의 학생 원본 혼입, 캔버스 좌표/히트 영역 불일치, 서비스워커의 구버전 혼합이다. 각 수정은 해당 실패 경로를 다시 검사해야 한다. 원본 에셋 삭제나 전면 재설계는 제안하지 않는다.

## 남은 검증

- 실제 태블릿 터치·전자칠판 청감/가독성·학생 독립 플레이·교실 AP 30명 동시 접속은 미검증이다.
- 연속 완주 중단의 원인을 앱/브라우저/검사 환경으로 분리해야 한다. 예전 38/38·261/261·완주 보고서를 이번 전체 통과로 재사용하지 않는다.
- 확인되지 않은 제작·상업 이용 조건은 사용자의 실제 원본 기록 확인이 필요하다.
- 수정 전 진단 보고서이므로 구현 후 빌드·콘솔·저장·모든 화면·운영 동일성 검증은 별도로 수행해야 한다.
