## 확인하고 고친 문제

### 도시 기록 카드가 태블릿에서도 너무 얇았음 — 수정 완료

원본 `token(...,345,48)`의 실제 터치 높이는 1024×768 교사 모드에서 37.35px였다. 어린이가 글자 근처를 정확히 누르지 못하면 선택이 빗나가는 문제다. 큰 캔버스에서는 세로 hitArea만 48 CSS px로 보정했다. 작은 캔버스에서는 카드와 대상 사이 거리 자체가 48px 미만이므로 확대만 하면 표적을 가린다. 이때 좁은 드래그를 끄고 **기록 카드 고르기→기록 선택→시기 선택** DOM 경로를 제공한다. 기존 `connect()` 판정·관찰 기록을 그대로 공유하며 정답 위치를 가르치지 않는다. 관찰 전에는 보조 버튼이 비활성이고, 두 시기를 본 뒤 열리므로 관찰 조건도 유지된다.

수정 위치: `src/adventure/city.js:49`. 카드3개·시기2개는 실제 48px 이상, 글자20px. 농장도 '아주 오랜 시간 뒤'를 그대로 유지한다. 두 해상도·세 장소에서 재검했고, 모달은 915×412에서도 내부 스크롤 없이 들어온다. 기존 드래그는 충분한 공간이 있는 화면에서 유지한다.

### 교사 넘기기 버튼이 학습 선택지를 덮었음 — 수정 완료

1280×800 도시 장면에서 '교사 시연: 다음 단계로' 버튼이 오른쪽 기록 카드 일부를 덮었다. `src/rounded-ui.css`의 좁은 override로 버튼을 상단 교사 시연 띠 안으로 옮겼다. 1000px 이하는 띠의 중복 설명만 숨기고 시연 종료·넘기기 버튼은 유지한다. 915/1280 스크린샷에서 가림 해소를 직접 확인했다. 학생 모드에는 적용되지 않는다.

### 강 이름표를 작은 화면에서 읽고 고르기 어려웠음 — 보조 조작 추가 검증

공통 담당이 추가한 '이름표 고르기' 모달에 공용 캡슐 스타일을 적용하고 실제 터치를 확인했다. 모달은 세 이름만 보여 주고, 고른 뒤 기존 언덕의 빈 원을 직접 눌러야 한다. 각 원에 답 이름이나 정답 색은 붙이지 않았다. 기존 직접 드래그도 유지된다.

## 잔여 문제·재현·권장 범위

1. **소형 폰 가로의 여러 캔버스 드래그/글자 축소(C3·C20)**. 우선순위 P1. 915×412 교사 시연에서 화산 주사기 단계 또는 암석 특징 카드 단계로 이동하면 드래그 높이가 각각 약16.8/18.38px로 측정된다. 손가락으로 작은 대상을 정확히 집기 어렵고 카드 글씨를 읽기 어렵다. 근거는 `deep-ui-compact.json`의 실제 변환값, `layout/915-*.png`. 공통 `api.drag()` 전체 hitArea를 무턱대고 키우면 인접 대상이 겹칠 수 있어 적용하지 않았다. 강·도시처럼 각 메커니즘별로 DOM 선택/조작 대체를 확장하는 것이 권장된다. 영향 범위가 커 별도 UI 계약·휴대폰 전수 실터치 회귀가 필요하다. 주력 태블릿의 본문 하한 미달과 혼동하지 않는다.
2. **키보드 전용 완주 경로(C11)**. P2, 코드 추정. 지도·공통 HUD·도시 기록 선택은 검증했지만 모든 캔버스 드래그를 대체하지 않는다. 각 활동의 키보드 가능한 DOM 대체를 같은 판정 함수로 연결하는 방식이 적합하다.
3. **실기 제스처/텍스트 확대(C19·C25)**. 미측정. iPad/Safari와 학교 Android 태블릿에서 실기 확인해야 한다. 측정하지 않은 합격 판정을 내리지 않았다.

미니 전후 그림 안의2~3px 글자는 같은 카드 아래에 이름과 설명이 다시 있고 선택해야 하는 문구가 아니어서 C20 실패 목록에서 제외했다. 전체 그림이 작은 것과 핵심 학습 선택지의 작은 글자를 구분했다.
