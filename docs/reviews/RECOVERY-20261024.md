## 검수 범위 확장

전체 흐름 검사를 다섯 장소에서 끝내던 기존 범위에서 대표 기록 다섯 개 선택, 마지막 도전 세 개, 엔딩, 인증서, 최종 상태 새로고침 복원까지 확장했다. 잘못된 전이 답과 불완전한 경로가 통과하지 않는지도 검사한다.

## 최종 기능 재검증

- 학생 모드의 30개 발견·개념창 10개·보상 5개를 다시 완료한 뒤 검사 생성 학생 상태를 보관했다. `.work/recovery-check/flow-complete.log`에 각 장소 완료가 남아 있다.
- 마지막 도전 검사는 이 상태를 **새 테스트 컨텍스트에 복원해** 별도로 실행했다. 대표 기록 다섯 개 선택 → 강 방향 전이 → 두 관찰 근거로 암석 분류 → 도서관 밖 안전 경로 → 엔딩 → 인증서 → 새로고침 후 `finished=true`, `final.round=3` 보존까지 통과했다. 런타임 오류와 HTTP 400 이상 응답은 모두 0이었다.
- 마지막 검사의 `concepts`·`rewards`는 `null`로 기록했다. 이 실행이 해당 과정을 새로 수행한 것처럼 세지 않기 위해서다. 이전 실행에서 실제 획득한 30발견 상태라는 점은 `resumedStageState`, `stageEvidenceSource`로 구분했다.
- 마지막 검사 근거: `.work/recovery-check/flow.json`, `flow-final-only.log`, `flow-ending.png`, `flow-certificate.png`.
- 재생 버튼 수정 후 실제 포인터 클릭으로 재생 함수 호출, `playing`, `timeupdate` 진행을 확인했다. `.work/recovery-check/media.json`.
- 초기 로딩을 1280×720 새 Chrome 컨텍스트 3회에서 직접 측정했다. UI와 글꼴 확인 시점은 1.053초 / 0.359초 / 0.391초, 초기 리소스 전송량은 각 2,372,280바이트였다. 로컬 서버·속도 제한 없음 조건이며 실제 교실 네트워크 값은 아니다. `.work/recovery-check/loading.json`.
- 변경 후 **1024×768, 1280×720, 1920×1080의 261/261 검사 통과, 런타임 오류 0**을 확인했다. 각 크기에서 30단계, 단계별 힌트, 개념 영상 열 개의 재생·규격, 시작·지도·설정·시연 이동창·최종 연결·엔딩·인증서를 검사했다. `.work/recovery-check/layout-final/results.json`, `layout-final.log`.

## 검사 한계

- 다섯 장소의 상당수 조작은 앱의 조작 도움 버튼을 사용했다. 이 도움은 알맞은 대상이나 답을 적용하므로, 검사 통과는 진행 연결과 저장의 근거이며 학생이 스스로 정답을 발견할 수 있음을 증명하지 않는다.
- 학교·바깥 안전 경로는 실제 캔버스 좌표 클릭으로, 마지막 경로는 실제 포인터 그리기로 검사한다.
- 개념창을 열고 계속한 결과와 영상 재생 검사는 구분한다. 흐름 검사는 개념창 열기·계속하기를, 다중 해상도 UI 검사는 영상 열 개의 실제 재생과 8초·1280px 규격을 확인했다.
- 실제 태블릿 기기의 터치, 교실 30명 동시 접속, 서로 다른 탭의 동시 저장 충돌, 운영 배포본 동일성은 이 보고서의 측정 범위에 포함하지 않았다.
- 48px 터치와 글자 크기 자동 검사는 DOM 요소를 대상으로 한다. 캔버스 안 모든 글자의 실제 표시 크기와 색 대비를 전수 측정한 결과는 아니다.
- 전 항목에 대한 새 점수는 산정하지 않았다. 직접 측정하지 않은 항목을 현재 통과로 간주하지 않는다.
